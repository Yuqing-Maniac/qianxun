千寻 文件秒搜 1.2.2（Windows 10／11 版）
=====================================

Everything 式文件名秒搜：全盘文件名索引常驻内存，输入即出结果；新建、改名、删除约 1 秒内同步。

一、运行环境
  Windows 10 / 11（64 位）。无需安装，无需管理员权限，不写系统目录。
  本包里的 Python 3.13 不能在 Windows 7 上运行。Windows 7 请用原生版压缩包。

二、使用
  1．解压后顶层只有 QianXun.exe 和 QianXun 文件夹。把这两样放在一起（如 D:\Tools\）。
  2．双击旁边的 QianXun.exe。不要只把 exe 拷走。第一次运行会在桌面建立快捷方式，图标来自这个 exe。
  3．首次启动扫描全部本地磁盘（约每秒数万个文件），之后从缓存秒开。
  4．关闭窗口时程序最小化到任务栏通知区域，继续实时索引；右键托盘图标可退出。

三、搜索语法（与 Everything 一致，F1 查看完整说明）
  空格＝与　|＝或　!＝非　* ?＝通配符　"…"＝短语
  含 \ 或 / 的词按完整路径匹配（/ 等同 \）：Users\文档　d:/项目 报告
  ext:pdf;docx　size:>100mb　dm:today　file:　folder:　regex:　path:

四、常用快捷键
  Ctrl+Alt+F　全局唤出／隐藏（工具 → 选项中可修改或关闭）
  Enter 打开　Ctrl+Enter 打开所在文件夹　Ctrl+C 复制文件　Ctrl+Shift+C 复制路径
  F2 重命名　Delete 移到回收站　Alt+Enter 属性

五、选项（工具 → 选项）
  · 索引范围：留空＝所有本地磁盘；可改为指定文件夹。
  · 可移动磁盘（U 盘、移动硬盘）：插入后自动加入索引，拔出后自动移除；
    “安全弹出”时程序会立即释放该盘，不会提示“设备正在使用”。
  · 网络驱动器：默认不索引，可勾选开启。
  · 登录 Windows 时自动启动（后台托盘）。
  · 工具 → 创建桌面快捷方式。
  内置排除：各盘 $Recycle.Bin、System Volume Information，以及 Windows\WinSxS。

六、数据位置与卸载
  配置、索引缓存、日志：%LOCALAPPDATA%\QianXun\
  便携模式：在 QianXun.exe 同一目录新建空文件 portable.txt，数据改存到同目录的 data 文件夹。
  卸载：退出程序，删除整个文件夹和 %LOCALAPPDATA%\QianXun\；若开启过自启，先在选项中取消。

七、常见问题
  · 首次运行出现“Windows 已保护你的电脑”：程序未做数字签名，点“更多信息 → 仍要运行”。
  · 从网上下载的压缩包：建议先右键 → 属性 → 勾选“解除锁定”，再解压。
  · 无权限访问的目录（其他用户的文件夹等）会静默跳过。
  · 联接点、符号链接只作为条目收录，不进入其中，避免重复和循环。
  · 问题排查：工具 → 打开日志目录，查看 qianxun.log。

八、增量升级
  从 1.1.0 升到 1.2.0，以及换到 1.2.2 的入口布局，都只能换完整包。发布页上的完整包是绿色版 tar.gz 和 zip、Windows 10／11 zip、Windows 7 原生 zip。
  更换 Python、Qt、启动器或原生 exe，也只能换完整包。
  增量包的文件名是 qianxun-<版本>-incremental.zip。已经在用 1.2.0 或更新版本时，打开“帮助 → 增量升级…”，
  选中这个 zip，再点确定。不需要命令行。
  1.2.0 的增量包与已经装好的 1.2.0 相同，确认后不改文件。以后的增量包把起始版本写成 1.2.0，
  或写成这台机器上已经装好的更高版本。目标版本取打包时程序里的 VERSION 行。
  维护者在仓库根目录执行：
  python3 app/qianxun.py --pack-incremental 1.2.0 . _work/dist/qianxun-1.2.0-incremental.zip
  增量升级有这些限制。新的 qianxun.py 要等当前进程退出、新进程启动之后才运行。
  只关窗口会留在通知区域，程序仍是旧的。/opt/qianxun 和 deb 安装目录这个菜单写不进去。
  单文件版释放出来的目录会被拒绝。原生 exe 没有这个菜单。这个 zip 不能更换 python3.13 或 Qt 库。
  复制到安装目录以外的菜单图标不会更新。增量包没有签名。
  写入中途崩溃时，下次启动会把 qianxun.py 恢复成升级前的文件。
  写进 qianxun-portable 的补丁，可能在下次从 U 盘启动且脚本内容不同时被盖掉。
