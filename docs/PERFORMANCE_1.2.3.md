# 千寻 1.2.3 性能优化验证

## 修改范围

Python 共用引擎与 Qt 界面，Windows 与麒麟均使用这份代码。未修改搜索语法、匹配规则及原生 C++ 搜索实现。索引文件格式仍为 3，可读取原有缓存。

- 目录子项、预排序编号、搜索缓存和界面结果采用 32 位紧凑数组。
- 保存索引时以生成器构造数值数组，避免百万个临时整数对象。
- 文件大小、时间变化不会单独触发全量名称重排。
- 搜索与排序放入后台线程；最多一个正在执行的任务和一个最新待执行请求。旧查询、旧索引代次的结果不会覆盖新结果。
- 界面绘制不等待搜索持有的索引锁。搜索完成后刷新；计算期间暂不执行旧选择的文件操作。
- Qt 列表初始只显示 2000 行，滚动继续加载。总数、搜索匹配和 CSV 导出保留完整结果。显式全选和 Ctrl+End 会加载全部显示行，超大结果下该操作仍可能较慢。
- Linux 属性补扫每批最多读取 256 项或约 10 毫秒，检查已监控/失效条目每批最多 2048 项；目录检查每 128 项暂停 5 毫秒。单个慢文件系统调用仍无法抢占。

## 本机对比（2026-11-15）

同一 Windows 主机、同一缓存（1,355,584 条目，164,060 目录）、同一 Python 3.14.7 和 PyQt5 5.15.11 测试环境。Qt offscreen 界面，不启动后台文件监控，保留真实搜索、排序和列表布局。基线取修改前 Git HEAD 源码。两版使用相同十次查询序列：py、readme、空、json、空，重复两轮。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 索引与名称预排序工作集 | 403.4 MB | 312.6 MB |
| 界面首次空白搜索工作集 | 528.1 MB | 337.7 MB |
| 十次搜索后的工作集 | 534.4 MB | 342.0 MB |
| 十次搜索后的私有内存 | 529.1 MB | 319.9 MB |
| 测试过程峰值工作集 | 547.9 MB | 449.7 MB |
| 十次搜索及界面刷新总耗时 | 38.57 秒 | 2.24 秒 |

这是针对该数据集的单次对比，不是所有电脑的保证，也不是麒麟真机结果。用户正常启动时还包括目录同步、实时监控等额外开销，不能把上述数值当作完整进程的固定占用。

另用已安装版 Python 3.13 运行库测量引擎：首次压缩修改使空白搜索工作集从约 453.5 MB 降至 363.5 MB。这个阶段尚未包含最终的界面按需显示改动。

## 验证

- Windows 真机：临时目录首次扫描、文件创建、改名、删除、退出保存与缓存重载通过。测试仅使用临时数据目录，不修改用户索引。
- 紧凑数组占用上限、四列正反排序、包含删除条目的缓存读写、属性变化不重排、补扫批次限制、后台任务结果一致性通过。
- Qt 界面：搜索持锁时绘制不阻塞；计时器仍运行；快速连续查询只显示最新结果；重建后拒绝旧结果；按需加载完整结果通过。
- 原搜索属性测试在 Windows 上显式模拟 POSIX 路径及 surrogateescape，修改前后均 3000 组、零差异。这不替代 Linux 文件系统或 inotify 测试。
- 首轮 CI 的 Linux 引擎、搜索、资源测试、PyQt5／PySide6 后台搜索测试与原生编译全部通过。另增加修改前／修改后完整 Linux 回归作对照。
- 增量包 ZIP 完整性、ASCII 包内路径、新版升级器在临时安装目录应用与源码一致性通过。发现并修复旧 Windows 升级器只读句柄 fsync 回滚：旧 1.2.2 仍需手动覆盖源码，不能假定旧菜单能成功安装新包。

## 边界

此机未安装 WSL，不能直接执行 Linux 全套回归；麒麟飞腾硬件的内存、磁盘负载和长期运行情况仍需真机验证。Python 后台线程仍受 GIL 影响；极端正则和全选超大结果不是本次的硬实时保证。失效条目在写出缓存时会清除，但常驻索引尚未增加在线压缩回收，频繁增删文件的长期压力需另做耐久测试。
